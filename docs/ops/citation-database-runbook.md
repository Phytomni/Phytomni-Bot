# Citation Database Runbook

This runbook covers the operator-owned citation SQLite artifact used by the
Bot's cited-result enrichment. The artifact is built offline, mounted into a
serving process, and never generated by MCP or HTTP request handling.

## Scope and evidence

This procedure applies only to citation metadata used by
KnowledgeAgent, ReviewAgent, and BriefGeneAgent. `GAUSS_DSN`, GaussDB, and
relay BI remain in use for unrelated database paths. Citation lookup has no
GaussDB fallback.

Bot-local tests prove the builder, read-only validation, formatting, and
startup ordering contracts. They do not prove an operator mount, a real
backend request, Web rendering, staging, production, or activation. Record
those separately as evidence owned by the corresponding operator or release
owner.

## Prerequisites and capacity

- Use Python 3.12-3.14 with the repository's locked development environment.
- Keep the audited JSONL source outside Git, the wheel, and the container
  image. Do not write the builder output into the source file.
- Build on a local filesystem with enough free space for the source, the
  temporary SQLite variant table, compaction, and the final artifact. For the
  2026-08-07 audited source snapshot, plan at least 20 GiB free before
  starting; measure capacity for any other source separately.
- Ensure the serving identity can traverse the parent directories and read
  the mounted artifact, while it has no write permission to the artifact or
  its mount.

The examples below use safe placeholders. Replace `<metadata.jsonl>` and
`<citation.sqlite>` only in an operator-controlled shell; do not put source
records, credentials, or host-specific values in tickets or logs.

## Offline build and validation

Build an artifact atomically from an explicit source and destination:

```bash
uv run python scripts/citation_db.py build \
  --source <metadata.jsonl> \
  --output <citation.sqlite> \
  [--expected-sha256 <lowercase-sha256>]
```

Validate an existing artifact independently:

```bash
uv run python scripts/citation_db.py validate \
  --database <citation.sqlite>
```

Successful `build` and `validate` commands print one compact JSON summary and
exit `0`. The summary fields are:

```text
schema_version
source_sha256
source_record_count
unique_id_count
imported_record_count
exact_duplicate_row_count
conflict_id_count
quarantined_row_count
missing_doi_count
invalid_doi_count
missing_title_count
```

The default summary does not print conflict IDs, source values, SQL, or
database paths. A build or validation failure exits `1`; the CLI reports a
fixed `citation_db_build_failed` or `citation_db_validation_failed` message
without exposing the underlying artifact content. A malformed command exits
`2` through the normal argument parser.

## Conflict inspection

Conflicts are quality evidence, not an automatic build failure. The builder
quarantines every row for an ID with more than one canonical variant; runtime
lookup then treats that ID as a metadata miss and uses title-only formatting.

Inspect at most 100 selected conflict summaries explicitly, using an
operator-supplied ID list, without placing the list in default CLI output:

```bash
sqlite3 -readonly -json <citation.sqlite> \
  'SELECT file_id, conflict_json
     FROM citation_conflicts
    WHERE file_id IN (<quoted-id-list>)
    ORDER BY file_id
    LIMIT 100;'
```

The `conflict_json` value stores compact evidence for the variant count,
source-line list, and differing-field list, not full source records. The
explicit ID list and `LIMIT 100` keep inspection bounded; do not use an
unfiltered bulk query. Protect any inspection output as operator evidence.

## Mount and environment

Mount the validated artifact read-only at the operator's chosen service
location. The following is a documentation-only placeholder, not a live
deployment path:

```text
/var/lib/phytomni/citations/reference.sqlite
```

Set exactly one of these aliases in the serving environment, or set both
according to the repository's alias-precedence rules:

```text
CITATION_DB_PATH=<mounted-citation.sqlite>
PHYTOMNI_CITATION_DB_PATH=<mounted-citation.sqlite>
```

The configuration model remains lazy during package import and `create_app()`
construction. MCP `serve()` and the FastAPI HTTP lifespan require a nonblank
regular local file before transport or shared-client ownership begins. The
serving process opens SQLite with `mode=ro` and `PRAGMA query_only=ON`; it does
not create a missing file. Network filesystems are unsupported.

Startup failures use stable classes and path-free messages:

- `citation_db_configuration_missing` — neither alias supplies a value.
- `citation_db_artifact_unavailable` — the target is missing, unreadable, or
  not a regular file.
- `citation_db_invalid_sqlite` — the file is not readable SQLite.
- `citation_db_schema_mismatch` — schema version or application tables differ.
- `citation_db_metadata_mismatch` — metadata rows, keys, counts, or equations
  are invalid.
- `citation_db_integrity_failed` — SQLite integrity validation is not `ok`.

After successful startup, a bounded read failure is surfaced internally as
`citation_db_lookup_failed`; the answer remains successful and selected
references degrade to cleaned title-only output with
`citation_metadata_degraded=true`.

## Citation formatting contract

The three cited Agents use one formatter on blocking, native-run, and
terminal-stream projections. Inline markers keep their position and render as
`<sup>1</sup>` or `<sup>1,2</sup>`; consecutive numbers are not collapsed into
ranges.

Every selected structured reference has `formatted_citation`. Its available
fragments follow this escaped Markdown shape:

```text
Authors. Title. *Source* **Volume,** pages-or-article (Year). [DOI label](DOI URL)
```

Absent fragments are omitted, pages take precedence over `ar`, and a valid
`di` takes precedence over a valid DOI-host `dl`. A missing or invalid DOI
sets `doi_missing: true` and does not by itself set
`citation_metadata_degraded`. A missing, quarantined, or failed selected
record uses exactly the cleaned retrieval title and sets
`citation_metadata_degraded=true`. The display string never contains
`file_id`; the structured reference may retain it.

## Disposable startup and cited smokes

Before traffic activation, use a disposable MCP process and a disposable HTTP
process with the mounted artifact and the selected alias. Verify that startup
passes validation before the process accepts work, and capture only stable
startup status and redacted error output. Do not use a production process for
the first validation.

For example, under a disposable supervisor, start each serving boundary with
the placeholder mount:

```bash
env CITATION_DB_PATH=/var/lib/phytomni/citations/reference.sqlite \
  python -m mcp_server_phytomni.server

env CITATION_DB_PATH=/var/lib/phytomni/citations/reference.sqlite \
  phytomni-api
```

Then run both of these cited checks against the same disposable deployment:

1. Send one synchronous `phyto-knowledge` request and verify the normalized
   answer, `formatted.references`, and `formatted_citation`.
1. Send one `phyto-knowledge` request with `stream: true` and verify the
   terminal `TextMessageContent` plus `phyto.references` contain the same
   answer/reference contract as the synchronous response.

Use placeholders for any endpoint and credential when recording a command:

```bash
curl --fail --silent --show-error \
  https://<bot-host>/v1/chat/completions \
  -H 'Authorization: Bearer <operator-api-key>' \
  -H 'Content-Type: application/json' \
  -d '{"model":"phyto-knowledge","messages":[{"role":"user","content":"<cited-smoke-query>"}]}'
```

The stream smoke uses the same placeholder values:

```bash
curl --fail --silent --show-error --no-buffer \
  https://<bot-host>/v1/chat/completions \
  -H 'Authorization: Bearer <operator-api-key>' \
  -H 'Content-Type: application/json' \
  -d '{"model":"phyto-knowledge","stream":true,"messages":[{"role":"user","content":"<cited-smoke-query>"}]}'
```

Do not record an API key, source document, retrieved content, or host-specific
URL in this runbook.

## Replacement and rollback

Build a replacement in the destination directory so the final rename stays
on one filesystem. The builder validates, closes, and atomically replaces the
destination only after the new artifact passes schema, metadata, hash, and
integrity checks. A failed build leaves the previous artifact unchanged.

Runtime lookups use short-lived read-only connections. Requests that already
opened the prior artifact finish against that inode; the next lookup opens the
replacement. If a replacement is corrupt or incompatible after startup,
lookups preserve answers and degrade selected references to title-only until a
valid artifact is restored or the process restarts. A restart revalidates the
artifact and refuses an invalid one.

To roll back, restore the prior validated artifact and restart, or redeploy
the prior Bot revision and its matching environment. There is no request-time
GaussDB fallback in the SQLite citation revision.

## Warning and evidence redaction

Runtime citation lookup warnings contain only the fixed class
`citation_metadata_lookup_failed` and the current request ID when available.
They must not contain file IDs, database paths, SQL, source or database
values, credentials, or raw exception text. Startup errors expose only the
stable error class and configuration key. Public degradation exposes
`citation_metadata_degraded=true`; private per-document lookup status is not
public.

Keep evidence boundaries explicit:

- **Bot-local:** source-controlled tests and local gates prove the Bot
  contract only.
- **Web:** rendering of `<sup>` and Markdown DOI links requires paired Web
  renderer evidence.
- **Staging:** mounted-artifact startup and cited sync/stream smokes require
  staging evidence.
- **Production:** production mount, rollback, and health evidence require the
  production owner.
- **Activation:** traffic activation is a separate release decision and is
  not implied by a local or staging pass.
